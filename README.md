# Equal AI Design System

The revamped Equal AI app as code: tokens, typography, 22 handoff components, the typography-inventory surfaces, full screens and a clickable prototype.
Built from the five design guides in `../` (Primitives, Alias Tokens, Typography × 2, Dev Handoff).

```
equal-ds/
├── tokens/tokens.json        ← single source of truth (colours, gradients, type, spacing, radius, shadow, motion)
├── scripts/build-tokens.mjs  ← generates web + Compose tokens from tokens.json
├── SPEC.md                   ← component contract (dp measurements, token usage) shared by both platforms
├── assets/                   ← drop image assets here (see "Assets")
├── web/src/
│   ├── tokens/               ← GENERATED: tokens.css (CSS vars, light/dark, .eq-t-* type classes), tokens.ts
│   ├── foundations/          ← Text, Icon (+ icons.ts), Asset, EqualMark
│   ├── components/           ← React components (one .tsx + .css each)
│   ├── screens/              ← screen templates + EqualPrototype (clickable flow)
│   └── screens/              ← screen templates, flows and the clickable prototype
├── site/                     ← the design-system website (React + Vite, imports web/src live)
└── compose/                  ← Jetpack Compose library module (ai.equal.ds)
```

## The design-system website

```bash
npm install
```

```bash
npm run site
```

Opens at http://localhost:5190. The home page is the **App Map**: live Equal AI screens where you hover any part to name its component (Trace) and click to open its page. Every page renders the real components in Light, Dark or Both, and ⌘K searches tokens, components, icons and screens.

- `npm run site:build` writes a static build to `site-dist/` (hash URLs, so it can be hosted anywhere with no rewrites); `npm run site:preview` serves that build.
- Component pages come from `site/src/registry/components.tsx` (examples, props, tokens, Compose names, do / don't).
- Other scripts: `npm run tokens`, `npm run icons`, `npm run typecheck`.

## Use in a React app

```tsx
import './equal-ds/web/src/tokens/tokens.css';
import './equal-ds/web/src/styles/base.css';
import { ChatListItem, Button, Text } from './equal-ds/web/src';

<div data-theme="light">…</div>   // or "dark"
```

Colours: `var(--eq-text-primary)` in CSS, `color.textPrimary` in TS. Type: `<Text variant="body1" color="secondary">` or the class `.eq-t-body1`.

## Use in Android

The Android app is Kotlin (business logic) + Jetpack Compose (UI) + Lottie JSON (animations).

See `compose/README.md`. Wrap in `EqualTheme { }`; read `EqualTheme.colors`, `EqualTheme.type`, `EqualTheme.gradients`.

## Changing a value

Edit `tokens/tokens.json` → `npm run tokens`. Web and Android both update, so they can't drift. Never hand-edit generated files.

## Icons, emoji, categories & logo

- **Flat icons:** Material Symbols (Outlined 400) + the WhatsApp brand glyph, generated by `scripts/build-icons.mjs` (`npm run icons`) into web `icons.ts` **and** Compose `EqualSymbols.kt`, with identical paths.
- **Profile avatars** (supplied): `<ProfileAvatar variant="male" | "female" size={70} />`. Sources are in `tokens/brand/avatars/`.
- **Actions:** Unicode emoji (`<SmallActionChip emoji="📞" />`), not images.
- **Category icons** (16, supplied): `<ContactAvatar category="delivery" />`. Unknown caller = `na` (the sparkle). Files: `assets/category-*.webp`, Android `res/drawable-xxxhdpi/ds_category_*.webp`, downscaled from `../Catergory Icons/`.
- **Full logo** (official SVG `tokens/brand/equal-logo.svg`): `npm run logo` writes it into code for both platforms. `<EqualLogo height={20} />`, `<EqualMark />`; colour = `text/action` (green in light, lime in dark).
- **Mascot** (supplied): `assets/mascot-robot.webp`, drawn with `<Mascot size={40} />` on the AI Assistant card; the robot fills the box and the file isn't cropped.
- **Chat wallpaper** (supplied, `BG pattern.svg`): coded as a tinted alpha mask. The pattern stays one file and `chat/wallpaper-pattern` (#737373 @ 8%) tints it for light and dark. Sources: `tokens/brand/patterns/` (original + precision-rounded SVG). Rendered masks: `web/src/foundations/chat-pattern@3x.webp`, Android `drawable-nodpi/ds_chat_pattern.webp`.
- **Logo orb** (supplied): `logo-orb-light` (#00B140) in light mode, `logo-orb-dark` (lime) in dark mode, swapped by theme. Used for the AI avatar and FAB, via `<EqualOrb size={36} />`.

## Image assets

Every image slot is supplied. To add a new one, drop `<name>.png | .webp | .svg` into `assets/` (web picks it up automatically) and a same-named PNG/WebP into `compose/equal-ds/src/main/res/drawable-xxxhdpi/` (Android). Until then, a checkerboard placeholder renders at the exact size.

The WhatsApp logo on the action card is coded, not an image: the simple-icons glyph in `brand/whatsapp` (#25D366).

Supplied: mascot (awake and sleeping), both profile avatars and both gender busts, the assistant persona (`avatar-assistant`), the high-five, trash, Silent Mode, WhatsApp, Addresses-empty, Instructions-empty and Suggestions illustrations, the orb (light and dark), 16 category icons and the chat pattern.

## Derived tokens & conflicts

Tokens flagged `"derived": true` in `tokens.json` are not in the colour guide. Their values were taken from the screens and component references and are final; every text pair passes WCAG AA in light and dark.
Every conflict between the designs, and the decision taken, is listed on the site under *Reference → Spec conflicts*. Dark-mode values follow the dark screens in the flow designs (background #141414, dark strokes).

## Flows

The site's *Screens & flows* section has every state of the Profile, Addresses, Instructions and Contact Info flows, live, plus the clickable prototype. Source: `web/src/screens/FlowScreens.tsx`.

## Building a new flow

1. Compose screens from components in `web/src/screens/Screens.tsx` (every screen uses only DS components).
2. Wire navigation like `web/src/screens/Prototype.tsx` (a simple route stack plus sheets/toasts as overlays).
3. Add its states to `site/src/pages/Flow.tsx` so they're reviewable on the site in light and dark.
